## Category rules

- **chest**: what a container rolls: a root of the chest-loot scope, or any table a structure template container names (even outside the scope). Scope seeds are tables declared `minecraft:chest`, or untyped/generic under a `chests/` or `chest/` folder, plus everything they pull in (same rule as `gen_loot_config.py`).
- **chest sub**: in the scope but pulled into another chest table (loot_table entry, code-added inject pool, or a sub-table GLM such as Farmer's Delight's). Tuned together with chests.
- **block** / **entity**: declared type, or `blocks/` / `entities/` folder.
- **gameplay**: fishing, gifts (cat / hero of the village), bartering, advancement rewards.
- **code/config**: declared `minecraft:empty`; the owning mod fills it in code from its config (Lightman's coin tiers).
- **other**: anything else (mod inject tables not reachable from a chest, mod-internal tables).

## Chest loot by namespace

"roots" = tables a container rolls; "sub" = tables only pulled into other chest tables. "outside" = roots a structure places that the tuning scope misses (see the section below). "untyped" = roots with no `minecraft:chest` type, caught by path (LootJS `LootType.CHEST` still sees them when a container rolls them). "code pools" = tables of this namespace that another mod appends a pool to in code. "unindexed" = in the scope now but not in loot_index.json yet. "placed" = roots a structure template container names directly; the rest are assigned in code or by processors (vanilla code-built structures, YUNG's) or unused. "placed by" = namespaces of the templates doing it, with container counts. "folders" is where the tables live under `data/<ns>/loot_tables/`.
