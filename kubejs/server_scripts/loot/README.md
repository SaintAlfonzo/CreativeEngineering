# Chest loot overhaul

Pack-wide chest loot control: cut unwanted items, tune how often items show up, redistribute,
place in specific tables. KubeJS + **LootJS** (`lootjs-forge 2.9.1`), no extra mods.
KubeJS ignores this `.md` and the `.json` files here (it only loads `.js`).

## Files

## Tuning: remove / reduce frequency everywhere

1. Open `loot_config.json`, find the item under `items` (sorted by id; `where` shows each
   table's chance per chest, `chests` how many tables).
2. `"remove": true` → it never appears in any chest.
   `"frequency": 0.25` → it shows up a quarter as often, in every table it's in (per roll).
   Mod-wide or pattern rules go in `patterns`:
   `"@somemod": {"remove": true, "except": ["somemod:keep_me"]}`, `"/_sword$/": {"frequency": 0.5}`,
   `"#ns:tag": {"frequency": 0.5}`. An item's own non-default entry beats any pattern.
   Named groups, bans and packed food go in `07_rules.js` as calls instead (next section).
3. `/reload`. The log line `[loot-tuning] N rules -> rewrote T tables ...` and `/loottuning`
   say what happened.

**How it works (two stages, both rebuilt on every `/reload`):**

- **Pre-roll**: `ServerEvents.genericLootTables` hands us each raw loot-table JSON before the game
  parses it. For every table `loot_index.json` lists for a tuned item, the pools are rewritten:
  the item's weight is set so its per-roll chance is exactly `frequency ×` the old one (entry
  dropped for remove). `settings.slack` decides where the lost share goes:
  - `"redistribute"` (default) — to the other entries of the same pool, keeping their ratios.
    Chests stay as full as before, like deleting the entry in a datapack. Removing a heavy
    common item does make that pool's rarer entries more likely.
  - `"empty"` — to an added `minecraft:empty` entry. Every other item keeps its exact odds;
    chests get a little emptier.
  If an item is the only entry in its pool, the slack goes to an empty entry either way. Pools
  are never dropped (a mod may look pools up by name/index in code). Pools with composite
  entries (none in chest loot today) or `expand: true` tag entries (4, Terralith spires) can't be
  reweighted exactly, so a tuned item there is dropped or gets a `random_chance` condition.
- **Post-roll**: a LootJS modifier on every chest roll handles what the JSON pass can't see:
  items added by global loot modifiers (armortrims templates, FD/endportal/geode add_item,
  PneumaticCraft, simplehats, Lightman coins), pools mods add in code, and `#tag` entries.
  Removed items are stripped (the slot stays empty). Reduced items are kept with probability
  `frequency`, except in tables the pre-roll rewrite already covers for that item (the index
  `reach` list), so nothing is reduced twice.

## Script rules (`07_rules.js`): the pre-roll API

`global.lootTuning` (alias `L`). Item targets are the same as `patterns` (`'ns:id'`, `'@mod'`, `'/regex/'`,
`'#ns:tag'`, a JS regex, or a list), preferably `global.item` keys. Table filters: `'ns:table'`, `'@mod'`,
`'/regex/'`, a JS regex, or a list. Everything here is pre-roll: exact odds, the slot refilled from the pool.

| Call | Effect |
|---|---|
| `L.frequency(target, f, { except, tables })` | chance per roll x f: 0 removes, < 1 cuts, > 1 boosts (the rest of the pool pays) |
| `L.remove(target, { except, tables })` | never (in those tables) |
| `L.ban(target, { name, why, modLootOn, ownTables })` | removed, and LOUD (error-log banner + red chat to ops, repeated to ops on login) if `modLootOn()` reads true at a reload, if a table outside `ownTables` ships it, or if a chest roll ever produces it |
| `L.pack(packed, loose, { rate, max })` | splits each `loose` entry: the top `rate` of its roll becomes 1..max packed items (higher roll, more crates); nothing else in the pool changes |
| `L.packRate(r)` / `L.packBoost(tables, mult)` / `L.packExclude(tables)` | default rate (cap 0.9); multiply it in matching tables; skip tables |
| `L.companion(item, anchors, { rate, count, nbt, tables })` | `item` beside every anchor entry at rate x its chance |
| `L.add(tables, item, { share or weight, count, pool, nbt, conditions, except })` | new entry in each table's main pool (most item entries) at `share` of a roll |
| `L.addPool(tables, poolJson)` | append a whole pool |
| `L.restoreInjection(tables, poolJson, { mod })` | a mod's code-injected pool, re-added only where a jar/datapack override of the vanilla table made Forge skip it |
| `L.useVanilla(tables, { winner })` | swap a jar's override of a vanilla table back to vanilla's pools |
| `L.alias(missing, source or [pools])` | create a table containers name but nobody ships |

Precedence: bans, then an item's own `loot_config.json` entry, then patterns in file order, then script rules in
call order. Per table the order is alias, useVanilla, addPool/restore, add, pack/companion, tuning, so a rule on a
packed or added item still applies, and removing a packed or added item switches it off. `#tag` rules read the tag
from the same reload (`95_tag_capture.js`); define tags in `tags/loottags.js` with `global.tags`.

Post-roll (LootJS) is used only for items the catalog marks `post_roll_only` (a loot modifier or mod code adds them):
the same rules strip or thin them after the roll, and the log lists them each reload. The `10`-`40` scripts are
for what only LootJS can do: edits scoped by structure / biome / dimension / player, stack caps, per-roll code.

**Regenerate the catalog** after adding/removing/updating mods: `/dumploot` in game (optional,
but it's how code-added pools like Botania's are found), then `python3 tools/gen_loot_config.py`,
then `/reload`. Items you edited that vanish are kept with `"missing": true`.

**Verify**: `/loottuning`; or `/dumploot` and diff a touched table against the raw jar JSON
(the export now shows the tuned weights); or `99_debug.js` logging for the post-roll half.

**Scope**: "chest loot" = tables of type `minecraft:chest`, untyped tables under a `chests/` /
`chest/` path, and everything they pull in (loot_table entries, code-added inject pools,
loot modifiers that roll a whole sub-table: Farmers Delight, oldguns). Mob drops, block drops, fishing and bartering are
untouched even when they contain the same item.

## Workflow for the LootJS-only scripts (10-40)

1. **Enumerate.** Test world → `/dumploot` → `kubejs/exported/loot_tables/<namespace>.json`,
   one file per namespace: every table as loaded (datapacks + pools mods add in code). Global
   loot modifier output is NOT in it — see `report` in `loot_index.json` for those.
2. **Edit** the concern scripts. Everything is server-side — plain `/reload` applies it.
3. **Verify.** Uncomment `event.enableLogging()` in `99_debug.js`; open chests in **fresh
   chunks** across several structure types; watch `logs/latest.log` for `[LootJS]` lines.
4. Temporarily set `config/lootr-common.toml` `report_unresolved_tables = true` to catch any
   table id Lootr can't resolve.

## LootJS 2.9.1 API cheatsheet (this version — 2.x, NOT the 3.x `LootJS.lootTables` rewrite)

LootJS 2.x is a global loot modifier: every action runs on the **already-rolled** item list.
It can add, remove, replace or modify stacks, but it can never change a table's weights.

```js
LootJS.modifiers(event => {
  // TARGET  -> returns a builder
  event.addLootTypeModifier(LootType.CHEST)                 // every chest roll (by context, any table)
  event.addLootTableModifier('minecraft:chests/igloo_chest')// exact id
  event.addLootTableModifier(/betterstrongholds:chests\//)  // regex on table id
  event.addLootTableModifier(['a:x', /b:y/])                // OR of several
  event.disableLootModification('ns:chests/x')              // exclude a table

  // BUILDER ACTIONS (chain)
  .removeLoot(filter)                       // filter: 'id' | '#tag' | /regex/ | [..] | ItemFilter.XXX
  .addLoot(LootEntry.of('minecraft:diamond'))
  .addWeightedLoot(LootEntry.of(Item.of('minecraft:diamond', 3)).withWeight(5))
  .replaceLoot(filter, newEntry, true /*preserveCount*/)    // swaps rolled stacks; weight is meaningless here
  .modifyLoot(filter, stack => stack.withCount(1))          // post-roll stack tweak
  .pool(p => { p.addLoot(...); p.addLoot(...) })            // add a whole extra pool
  .apply(ctx => { ctx.removeLoot(...); ctx.addLoot(...) })  // full custom, per roll
  .logName('CE/loot/...')                                   // shows in enableLogging output

  // BUILDER CONDITIONS (gate the whole modifier)
  .randomChance(0.3)
  .anyStructure(['#minecraft:village'], false)              // (tags/ids, matchExact)
  .anyBiome('#minecraft:is_overworld')
  .anyDimension('minecraft:the_end')
  .matchLoot(ItemFilter.WEAPON)

  // LootEntry
  LootEntry.of('3x minecraft:iron_ingot')                   // OutputItem syntax
  LootEntry.of(Item.of('minecraft:iron_ingot', 3))
    .withWeight(15)
    .when(c => c.randomChance(0.5))                         // per-entry chance
  //  NOTE: LootEntry.withChance(int) is a misnamed alias of withWeight — don't use it.
  //  count RANGE on an added entry needs a set_count LootItemFunction (.addFunction(...)).
})
```

`ItemFilter` constants: `ARMOR WEAPON TOOL SWORD PICKAXE AXE SHOVEL HOE FOOD POTION
ENCHANTED ENCHANTABLE DAMAGEABLE DAMAGED HAS_TIER PROJECTILE_WEAPON BLOCK` +
`ItemFilter.and/or/not(...)`, `ItemFilter.custom(stack => bool)`, `ItemFilter.hasEnchantment(rl)`.

To edit a table's JSON before it's parsed (what 05_tuning.js does), use KubeJS itself:
`ServerEvents.genericLootTables(e => e.modify('ns:path', b => { b.pools ... }))`. `b.pools` is
the raw Gson array; `b.type` is forced to `minecraft:generic` by the event, so set it back. Calling
`modify` on an id that doesn't exist creates an empty table — throw inside the callback to abort.

## Landscape facts

- **Filter on loot TYPE, not path.** ~250 modded container tables are NOT under `.../chests/`
  (Terralith `village/`·`ruin/`·`spire/`, The Missing Villages `village/<biome>/`, MES flat,
  Towns & Towers `village/`+`outpost/`, Philip's Ruins **`chest/`** singular, YUNG's Better
  Dungeons `<dungeon>/chests/`). `LootType.CHEST` catches them all; path regex won't.
- **LootJS runs after Forge GLMs.** It sees & can edit entries injected by Farmers Delight,
  armortrims, everythingcopper, simplehats, Lightman's `coins_in_chests`, and Botania's inject pools.
- **Mods add pools in code** (`LootTableLoadEvent`): Botania, Supplementaries, Sophisticated
  Backpacks, MineColonies, CC:Tweaked, Immersive Weathering, Chalk append `loot_table` pools
  pointing at their inject tables. They're in `/dumploot` but not in any JSON file.
- **Lootr fills per-player at open time**, not at chunk gen — test in fresh chunks.
- Duplicate item entries in one pool are legal (Terralith) — the tuning handles each one.
