## shield-mechanics-findings

Research behind the **shield tiers** feature (per-damage-type reduction %, plus potion effects on shielder/attacker of a blocked hit; vanilla iron shield currently = 100% and is to be lowered later). Research written 2026-09-20; the same day the user answered the open decisions at the bottom (config-heavy; tiers CAN block fire/magic via a widened isDamageSourceBlocked; durability scalable per percentage; ignore Stradpole/Croc; IE shield stays separate; 7 new items, vanilla look, no recipes) and it was built - see [shields](shields.md). Derived by `javap` on the mapped forge jar in DecompiledMods + mod jars; SRG names via tsrg2 x client_mappings join (`~/.gradle/caches/forge_gradle/minecraft_repo/versions/1.19.2/`).

**Vanilla/Forge path (LivingEntity.hurt, server only):** `onLivingAttack` -> `isDamageSourceBlocked` (m_21275_) -> `ForgeHooks.onShieldBlock` posts `ShieldBlockEvent(blocker, source, amount)` -> if not cancelled: `hurtCurrentlyUsedShield(amount)` (only if `shieldTakesDamage`) -> `amount -= getBlockedDamage()` -> `blockUsingShield(attacker)` (non-projectile) -> `blocked=true` -> `actuallyHurt` (LivingHurtEvent fires even at amount 0).
- 100% is not a stored value: `ShieldBlockEvent.dmgBlocked` defaults to full amount. `setBlockedDamage(x)` clamps to [0, original] so it can only *lower* blocking. Nobody in the pack listens to the event (jar scan) - clean slate.
- `isDamageSourceBlocked` gates: not `isBypassArmor`, `isBlocking()`, not piercing arrow, `getSourcePosition()!=null`, XZ dot(view, toSource)<0 (front 180deg). So fire/magic/fall/drown etc. can never reach the event. 1.19.2 has class-based `DamageSource` flags (isProjectile/isExplosion/isFire/isMagic + getMsgId), NOT datapack damage_type tags.
- `isBlocking` (m_21254_): `UseAnim.BLOCK` **or** `ToolActions.SHIELD_BLOCK`, plus `getUseDuration - useItemRemaining >= 5`. Shield identity must be `getUseItem().canPerformAction(SHIELD_BLOCK)`, never `instanceof ShieldItem`.
- Shield durability = `hurtAndBreak(1+floor(amount))` if amount>=3, from the PRE-block amount (not scaled by reduction). Fully vs partially blocked both set `blocked=true`: hurt feedback = entity event 29 (shield sound), no hurt animation; `knockback(0.4)` still applies regardless.
- Forge patches: `Player.disableShield` cooldown goes on the *used* item (not Items.SHIELD), flat 100 ticks; `Player.blockUsingShield` uses `ItemStack.canDisableShield(attackerWeapon, shield, ...)` (IForgeItem hook on the attacker's weapon).
- LivingHurtEvent/KubeJS `EntityEvents.hurt` (read-only in this build) fires on fully blocked hits -> existing `global.toolEffects.onHit` echo/dragon effects probably still apply through a full block (inferred from bytecode, unverified in game).

**Mods touching shields:**
- responsiveshields: one `@ModifyConstant` on isBlocking's `5` (config Raise Time=0). Global, no damage logic.
- IE `immersiveengineering:shield` = `IEShieldItem extends UpgradeableToolItem` (NOT ShieldItem), BLOCK anim + DEFAULT_SHIELD_ACTIONS. Upgrades (flash/shock/magnet) run from IE's `EventHandler.onLivingAttacked` (LivingAttackEvent, before vanilla): needs dmg>=3 and IE's own copy `Utils.canBlockDamageSource` (verbatim copy of vanilla arc test). Shock upgrade discards projectiles + cancels the event, so vanilla block path never runs for them (no ShieldBlockEvent, no durability loss).
- AM `shield_of_the_deep` = plain Item (BLOCK + DEFAULT_SHIELD_ACTIONS), no extra logic. AM `skelewag_sword` = SwordItem that also blocks (same actions).
- AM attackers bypass `hurt` entirely when target `isBlocking()`: EntityStradpole.onEntityHit, EntityCrocodile bite -> no damage, no arc check, no event, just shield wear (+stun for croc). SharkToothArrow overrides `damageShield`; VoidWormShot calls `disableShield`. Tiers via ShieldBlockEvent can't reach Stradpole/Croc (stay 100%).
- MineColonies: citizens override `isBlocking` (`instanceof ShieldItem`, no 5-tick delay) and `hurtCurrentlyUsedShield` (bleed-through: health -= max(0.5, armor-reduced amount*0.5), shield wear amount*0.5). Guard gear only equips `ShieldItem` subclasses -> new shield items that aren't ShieldItem are unusable by guards. Event listener also covers citizens (ShieldBlockEvent blocker is any LivingEntity).
- Other `isBlocking` readers only: SecurityCraft TaserItem, MCA GrimReaperMeleeGoal, geckolib/notenoughanimations (client anims). collective/worldedit/Quark/geodeforge hits are false positives.
- `everythingcopper:copper_shield` is a ShieldItem subclass (oxidation via NBT age) but is REMOVED in this pack (removed_items.js:82, metal_base_materials.js:45).
- Damage-pipeline mixins to know about: immersive_armors `MixinLivingEntity` (@Inject hurt HEAD; @ModifyArg on the `actuallyHurt` call = post-shield remainder, so multiplies with tiers), vinery (hurt HEAD, fire resistance only). Neither touches the block path.

**Pack side:** no KubeJS/creativeCommon shield code exists. Frameworks to mirror: `global.armorEffects` / `global.toolEffects` (startup `func/*.js` data + client tooltip + server handler), damage edits via Creative Common Forge listener (`MagicResistanceEffect` pattern, registered on `MinecraftForge.EVENT_BUS` in CreativeEngineering.java, knobs in CEConfig). KubeJS has `ForgeEventWrapper` but no ShieldBlockEvent binding of its own. `CETiers.java` is copper *tool* tier only, unrelated.

**Open decisions:** (1) do any tiers need to reduce damage vanilla can't block (fire/magic/unpositioned)? That needs a widened `isDamageSourceBlocked` mixin (IE's copy would diverge) or a LivingHurtEvent path instead of ShieldBlockEvent. (2) Scale shield durability with reduction? -> `setShieldTakesDamage(false)` + manual damage (also skips MineColonies bleed-through). (3) Patch AM Stradpole/Croc? (4) New tier shields need a real `ShieldItem` subclass (Creative Common) for MineColonies + vanilla-style rendering; KubeJS `useAnimation(BLOCK)` works for blocking but not for the banner/BEWLR render.
