# camo-walk-speed

> Framed/copycat blocks walk like their camo (CEConfig [surface.camouflage] copyCamo, was [camouflage_speed]); multi-material blocks use the newest-inserted material; BlockRunner tooltip line rewritten; hybrid wording in mods/ since 2026-09-27 (13:12 jar)

Moved from agent memory 2026-11-16 (last edited there unknown). Repo status docs win over any status line here.

Full reference and tests BR-14…21 are in `feature_writeup/blockrunner.md` §3.3. BR-17 (newest camo wins on framed double slab) passed in game 2026-09-27. Framed slab/panel count as hybrid-capable for the tooltip note (only those two merge by right-click; FramedBlocks BlockType FRAMED_SLAB/FRAMED_PANEL). Tooltip wording changed to "Speed Multiplier: %s, no matter its camo" (2026-09-27); built, but NOT copied to mods/ because the game was running (also the "(the newest one in a hybrid)" wording). Deploy it next time the game is closed.

Built 2026-09-27 in patcherMod `surface/` ([blockrunner-speed-tiers](blockrunner-speed-tiers.md), [patchermod-coremod](patchermod-coremod.md)).

- **Speed:** `mixin/BlockRunnerBlockStateMixin` (renamed from BlockRunnerStickyFacingMixin; hooks RETURN of BlockRunner's merged `blockrunner$tryAddBlockSpeed`, priority 1500) runs StickyFacing, then `CamoSpeed.afterBlockRunner`. On a block in `#creativeengineering:camo_speed` (= #blockrunner:surface/camouflage, set in blocktags.js), it reads the camo and swaps BlockRunner's modifier (same UUID and formula `factor*base - base`, ADDITION) for the camo block's own BlockSpeedManager factor. Skips while flying, and when the camo is empty or another camouflage block.
- **Camo lookup:** FramedBlocks `FramedBlockEntity#getCamo()`, double blocks `getCamo()`/`getCamoTwo()`. Copycats+ single-state via `ICopycatBlockEntity#getMaterial()`/`hasCustomMaterial()`, multi-state via `MaterialItemStorage#getMaterialMap()`. Create's own `CopycatBlockEntity`. The mod-specific code sits in `FramedCamo`/`CopycatsPlusCamo`, guarded by ModList.isLoaded. The FramedBlocks and copycats jars are in patcherMod/libs.
- **Newest material** (the user's rule for multi-material blocks): `FramedDoubleCamoOrderMixin` records the `secondary` flag on non-empty `setCamo`. It is persisted as the top-level key `creativeengineering:last_camo_second` in save (m_183515_/m_142466_), writeTo/readFromDataPacket and getUpdateTag (m_5995_)/handleUpdateTag. `CopycatMaterialOrderMixin` on MaterialItemStorage records the part on `storeMaterialItem` when it's custom, and follows `remapStorage`. It is persisted as the flag `creativeengineering:newest` *inside* that part's compound: `deserialize` turns every top-level key into a part, so a separate key would make a phantom part. Fallback when the newest part has been emptied: framed -> the other half; copycats+ -> remaining material if it's uniform; otherwise the flat tier.
- **Tooltip:** `CamoSpeedTooltip` (ItemTooltipEvent LOW, registered in CreativeEngineering ctor) replaces BlockRunner's `block.blockrunner.speedMultiplier` line, keeping its style. The lang keys `creativeengineering.tooltip.walk_speed.{camo,newest_camo,fixed}` read "matches its camo" / "matches its newest camo" / "%s, whatever its camo". Multi-material is detected from the item's block: IFramedBlock#getBlockType().isDoubleBlock() or IMultiStateCopycatBlock.
- Config `[surface.camouflage] copyCamo` (default true; moved from `[camouflage_speed]` on 2026-09-27, see [blockrunner-speed-tiers](blockrunner-speed-tiers.md)) must match on server and client. The user's live toml had it at **false** on 2026-09-27, so every frame showed "1.0, no matter its camo" and no hybrid wording.
- Hybrid wording (user's own, 2026-09-27): lang `walk_speed.newest_camo` = "Speed Multiplier: matches its camo (newest camo sets walk behaviors for hybrid blocks)". The camo *sinking* must never be mentioned in a tooltip (user).
