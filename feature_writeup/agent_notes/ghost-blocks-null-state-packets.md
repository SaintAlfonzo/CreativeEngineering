# ghost-blocks-null-state-packets

> Root cause: vanilla 1.19.2 section-update packet int-overflows state ids >= 2^19; fixed in Creative Common (SectionUpdateEncodeFixMixin + client repair); debug switch + diff tool also exist; status in feature_writeup/fixes_compat.md

Moved from agent memory 2026-11-16 (last edited there unknown). Repo status docs win over any status line here.

Symptom (dedicated server only, never singleplayer): planting Neapolitan magic beans, hoe-harvesting corn/flax, tree growth/chopping, WorldEdit/schematics leave ghost blocks (server has the block, client doesn't, or the reverse); relog or moving away fixes it. Cause seen in client logs/latest.log 2026-10-04: ~22k `Error executing task on Client` NPEs, `ClientboundSectionBlocksUpdatePacket.runUpdates` -> `ClientLevel.setServerVerifiedBlockState` with a NULL BlockState. The client's `Block.BLOCK_STATE_REGISTRY.byId(id)` returns null for an id the server sent, the NPE aborts the loop and drops the rest of that section's changes. Forge syncs block ids but not per-block STATE COUNTS, so a block with a different state count on server vs client shifts every later id. Which block is still unknown. (My first theories - render-only desync, Xaero/Rubidium/DH hooks - were ruled out by this log; DH mixins don't touch block packets.)

Built 2026-10-04 in Creative Common (1.0.4 jar in build/libs): `CEConfig.DEBUG` `[debug.block_state_sync] enabled` (+ maxDetailLines), `devtools/BlockStateSyncDebug`, client mixins `SectionUpdateNullStateMixin` / `BlockUpdateNullStateMixin` (redirect IdMapper.m_7942_ / FriendlyByteBuf.m_236816_, log raw null ids + positions + client state count), writes `logs/cdev_block_state_ranges_<client|server>.txt` (client at login / first bad packet, dedicated server at ServerStartedEvent, off-thread, ~8 s). `tools/diff_block_state_ranges.py client.txt server.txt [--id N]` names the first block whose state count differs. Needs the jar + switch on BOTH sides; the server fires ServerStartedEvent ~90 s after "Done".

Scratch-server baseline: 761,052 states / 14,243 blocks. Vanilla blocks carry extra states from some mod (stone 3, grass_block 44, podzol 4) - a mod adding properties to vanilla blocks is the first suspect for a client/server mismatch (not yet identified). Mixin side is untested in game.

Related: memory `scratch-server-verify`, [patchermod-coremod](patchermod-coremod.md), memory `debugging-with-latest-log`.

**ROOT CAUSE (2026-10-04, after the user's dumps showed identical client/server ranges):** vanilla 1.19.2 `ClientboundSectionBlocksUpdatePacket.write` packs `Block.getId(state) << 12 | pos` in INT math (ishl) then i2l; ids >= 2^19 (524,288) go negative, the reader decodes id - 2^20, byId returns null, NPE. ~237k states / 4,708 blocks affected (neapolitan beanstalk, supplementaries flax, quark, everycomp...). Singleplayer is exempt: local connections have no encoder/decoder in the pipeline. Fix built in Creative Common (1.0.4 jar in build/libs, not in mods/): `mixin/SectionUpdateEncodeFixMixin` (common; redirects writeVarLong m_130103_ in m_5779_ to mask to 32 bits) + client repair in `SectionUpdateNullStateMixin` (id < 0 -> +2^20) via `util/BlockStateIdOverflow`. Scratch server booted with it, mixin applied; real client/server join not yet tested. Repair only works below 2^20 = 1,048,576 states (pack has 761,052).
