## 1. Overview

While a world loads (singleplayer chunk progress screen, `LevelLoadingScreen`) or the client receives a level (joining
a server, changing dimension, `ReceivingLevelScreen`), a dark bar at the bottom of the screen shows "Tip:" in green and
one tip in white, wrapped to at most 360 pixels. A new tip rolls in every `cycleSeconds`. Tips come from a shuffled
deck that carries over between loads, so no tip repeats until every tip has been shown, and the same tip never shows
twice in a row across a reshuffle.

Mechanism after Loading Screen Tips 1.1.0 by UltrusBot (MIT, Fabric 1.19.x): same file format, same label colour.
The pack's version is written from that behaviour as Forge event handlers, without the upstream mixin or config library.

## 2. Reference

Tip files: `assets/<namespace>/loading_tips/<name>.json` in any client resource pack.

```json
{ "replace": false, "tips": ["A tip as plain text", "or.a.lang.key"] }
```

- Files are read in id order (namespace, then path). `"replace": true` drops every tip read before that file.
- A tip that is a lang key shows the translation; anything else shows as written (so a `%` in plain text is safe).
- Duplicates across files are dropped; blank entries are skipped.
- Each pack needs its own namespace: two packs with the same `<namespace>:loading_tips/<name>` id shadow each other
  (vanilla's top-pack-wins rule), so only one would be read.

Built-in packs (`resourcepacks/<folder>/` in the Creative Common jar, registered as required client packs, always on):

| Pack | Folder / namespace | Content |
|---|---|---|
| Loading Tips | `loading_tips` | 321 vanilla 1.19.2 tips; attribution in its `CREDITS.txt` and pack description |
| Creative Tips | `creative_tips` | the pack's own tips (14 so far: pack-accurate rewrites of audited vanilla tips) |

## 3. What the pack changes

- **Port route.** Loading Screen Tips 1.1.0 (the jar the owner downloaded) is a Fabric mod, so Forge does not load it
  (no `mods.toml`). It is MIT and tiny, so it became one Creative Common package (feature_porting.md tier: one
  handler) instead of a new jar. `ScreenEvent.Render.Post` draws the bar; no mixin.
- **Resource packs, not datapacks.** The loading screen is client side and a dedicated server's datapacks never reach
  it, so tips ship as resource packs (decided by the owner 2026-11-06).
- **Rolling deck** instead of upstream's random pick per interval: the owner asked for a rolling list.
- **Filtering of Loading Tips 1.2.1+26.1** (Naw7k, MIT, Fabric 26.1, so only its text is used): 532 tips, 340 kept, then 18 removed by the pack audit (322 left),
  192 dropped (appendix A), one reworded: "Baby mobs now have unique models instead of being shrunken adults!" became
  "Baby mobs have their own models instead of being shrunken adults." (the pack backports the 26.1 baby models,
  [baby_mobs.md](baby_mobs.md)). The 26.1-only changes to Golden Dandelions, Name Tags (craftable, trades),
  copper Note Block trumpets, baby mob sounds and the stonecutter are not in the pack, so those tips were dropped.
  Audited 2026-11-06 against the pack's mods, configs and dumps (TODO `ui/loadingtips #4`): 4 tips dropped as wrong (appendix B), 14 removed and rewritten in Creative Tips.

## 4. Limits and decisions

- The packs are required (always on): players cannot switch one off in the resource pack screen. `[loading_tips]
  enabled = false` hides the bar instead.
- Tips are English only. A translated pack can use lang keys instead of plain text.
- Upstream Loading Screen Tips' own default tips (lang keys in its jar) were not imported; only the Loading Tips text was asked for.
- The Fabric `loadingscreentips-1.1.0.jar` in `mods/` does nothing on Forge and can be removed.
- Chat announcements (planned, `ui/loadingtips #2`): KubeJS on the server, not Notify or Broadcasty (no confirmed
  1.19.2 build, and a script needs no new jar). A dedicated server loads no resource packs, so the script has to read
  the pack `tips.json` files itself (from the Creative Common jar, or a copy the build writes beside the scripts) to
  share the loading screen's list.
