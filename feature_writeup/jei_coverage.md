# JEI coverage gaps

A catalog of what players can do in this pack that JEI never shows: recipes it can't draw, recipe
types with no JEI category, and world interactions (right-click, drop-in, mob drops by mechanic...)
that no recipe describes. Each gap gets a suggested fix so the list can be worked down.

## 1. How JEI decides (crafting)

Read from the JEI 11.8.1.1034 jar (`VanillaRecipes`, `CategoryRecipeValidator`, `VanillaPlugin`):

- A recipe whose `isSpecial()` is false gets a page when its result is not empty and
  `getIngredients()` has 1 to 9 entries. Otherwise it's skipped (logged at debug level only).
- JEI's built-in crafting extension is registered for `CraftingRecipe` with the filter
  `!isSpecial()`. So an `isSpecial()` recipe gets a page only if:
  - a plugin registered a crafting extension for its class or a superclass, or
  - JEI or a plugin adds stand-in display recipes for it. JEI itself does this for exactly four vanilla
    classes: tipped arrow, shulker box colouring, suspicious stew, shield decoration.
- Which plugins do what was read from every mod jar's JEI plugin bytecode (`addCategoryExtension`
  calls, `addRecipes(RecipeTypes.CRAFTING, ...)` calls, recipe-manager plugins). The lists are
  `EXTENSIONS` and `STAND_INS` in the tool.

### Notes on part 1

- **Cycling pages (built 2026-10-22).** patcherMod's `CyclingCraftingJEI` adds one crafting page per recipe kind
  (61 recipes, ids in `CYCLING_PAGES` in the tool). Every input slot and the result are JEI focus-linked, so they
  cycle together, and a lookup (uses of red dye, recipes for a dyed bed) narrows the page to the matching variants.
  - **How a page is made:** `CyclingCraftingPages` builds candidate grids and runs the mod's own recipe on each
    (`matches`, then `assemble`, in `CraftingProbe`); only accepted grids are shown, with the real result and NBT. No
    mod classes are compiled against. A missing mod or recipe gives no page; a recipe that accepts no candidate is
    named in latest.log (`[jei cycle] no candidate grid matched`), with the totals in `[jei cycle] N crafting pages`.
  - **What cycles:** repairs (vanilla two-item, IE tools, Mimicream) over every damageable item, plain and
    enchanted; dyeing (armor dye on every dyeable-leather item incl. balloons and balloon arrows, Quark, IE
    colourable, Fantasy Furniture, Supplementaries Squared sacks, elytra, CC, Ender Storage per frequency slot,
    glass wind bell base x trim, flares, paint arrows, Botania lenses) one page per item with single dyes and two-
    and three-dye mixes where the recipe takes them; bedspreads (16 beds x patterned banners, and stripping);
    every Botania hidden recipe; balloon arrows per balloon colour; CC disks and printouts; wand cores; Customizable
    Elytra (dye, banner, cape, glow, split, combine); Fairy Lights copy colour; every IE gap; route copies; powder
    horn; Quark mixed-wood chest (each plank slot cycles through the wood types); drawer upgrades; banner, book and
    map copies; firework stars (shape x effect x colour), fades and rockets; the pack's elytra duplication.
  - **AE2 facades** are hidden from the ingredient list at runtime (thousands of generated items). The facade page
    (four cable anchors around a block, every facadable block) is found from the cable anchor; AE2's own plugin
    still adds its page when you look up uses of a block, so blocks show both.
- **Left as they are:** recipes another mod's JEI plugin already shows (the "plugin does cover" table) were
  checked by the user and stay with those plugins. Still uncovered: the 9 rows above (Armor Trims untrimming, CB
  Microblock, Etched labels, FD serving, FR pouring, Quark mixed furnace, SecurityCraft keycards, Sophisticated
  Core upgrade clear, map extending).
- **Botania** documents its hidden recipes in the Lexica Botania as well.
- **CB Microblock** is a combinatorial saw recipe (every block x every cut); an info page on the saws is the
  realistic fix.
- Recipes for items in `global.removedItems` are hidden from JEI on purpose
  ([jeichanges.js](../kubejs/client_scripts/jeichanges.js)) and are not gaps.

Not started. Input is already exported: `kubejs/exported/recipes/recipe_types.json` (from the same

## 4. Part 3: world interactions

Candidate catalog DONE 2026-10-22. Tabs BUILT the same day for the groups the user picked: see
[jei_world_tabs.md](jei_world_tabs.md). Not built yet from this list: hoe tilling / shovel pathing, FD rich soil,
Botania flowers, Neapolitan cauldrons, Quark map washing, Regrowth, nests, info pages (4.11). Sources: the pack's KubeJS event handlers,
patcherMod and the in-tree mods read directly; every third-party content mod checked from its jar (JEI plugin
classes, event handlers, data files). Rows marked **[I]** were inferred and not confirmed in the jar; check them in
game before building. The pack has **no JEI info pages at all** (`jeichanges.js` only hides items,
`fluid_jei.js` only adds fluids), so "info page" is always a new thing.

What the installed JEI addons cover, so these are not gaps: JER (mob drops from loot tables, ore distribution,
plant drops, dungeon loot), Just Enough Breeding (breeding foods, egg laying), jepp (paintings only), jerm (anvil
repair materials only), jess (sculk vibration frequencies only), jeimultiblocks (multiblock structures).
**JER does not apply global loot modifiers** (no `IGlobalLootModifier` reference in its jar), so every drop added
or changed by a GLM, LootJS included, is missing or wrong in JEI.

Candidates are grouped by the category that would cover them, because one category class can carry many mods.

## 5. Part 4: bulk sets

Generated or mass-variant content that floods the ingredient list or a recipe page. JEI 11.8 has no collapsible
ingredient groups (that came in later JEI), so the two tools are: hide the item from the list (it still shows inside
recipes), or move a set of recipes onto a page of its own. Counts from the 2026-10-22 dumps (28,621 recipes, 5,119
of them the pack's own; 19,164 items).

### 5.1 Recipe sets moved to their own page (BUILT 2026-10-22)

patcherMod `compat/jei/`: `PotionPagesJEI` + `RowPagesCategory` (rows: machine | inputs -> outputs, item or fluid
slots, potion fluids with their effect lines), `CanPagesJEI` + `CanCraftingCategory` (JEI's crafting grid, + button
fills a crafting table), shared `RecipeRows` (reads crafting, Create processing and IE bottling recipes, folds equal
ingredients into one slot with a count, adds grid leftovers as outputs, hides by recipe id). Each page set reads the
live recipes at every JEI reload and hides exactly what it re-shows; a recipe that doesn't fit a row (over 3 inputs
or 2 outputs) stays where it was. Config `[jei]` in `creativeengineering-common.toml`, all on by default; off leaves
the recipes on their old pages. Takes effect at the next JEI start (rejoin or `/reload`).
